# D29 — 요구사항 연결

실제 작업일: 2026-11-22 (KST). 날짜 없는 D번호 폴더로 기록합니다.

## 작업과 상태

심볼과 명시 테스트를 요구사항 ID에 연결합니다. 기본 프로젝트 계약 목록은 비어 있으며 사용자 요구사항을 발명하지 않습니다.

현재 상태: **구현·로컬 검증**.

관련 파일: `teamsync-requirements.json, teamsync/requirements.py`.

## 재현·증거

공통 명령: `python -m pytest -q`, `ruff check .`, `npm --prefix web test`, `npm --prefix web run build`. 관련 테스트는 `tests/phase2/`, 브라우저 검증은 `web/e2e/phase2_smoke.py`입니다.

[설계·범위](../docs/phase2/README.md)와 [실행 명령·결과·미검증](../docs/phase2/validation.md)을 확인하세요. 계획상의 완료 기준과 실제 결과를 혼동하지 않습니다. 다음 차수는 자동 진행하지 않습니다.

## 구현 판단과 완료 기준 검토 (2026-11-23)

### 작업

요구사항을 코드·테스트에 연결한다.

### 완료 기준과 실제 달성

완료 기준: 계약 ID와 symbol/test ID가 추적되며 임의 매핑을 만족으로 만들지 않아야 한다.

실제 상태: 형식·연결 검증, 사용자 실제 계약 작성은 별도.

### 구현 방법

requirements.py가 계약마다 참조 ID를 만들고 검사 결과와 연결한다.

### 대안과 선택 근거

LLM이 연결을 확정하기보다 명시 매핑을 택해 책임 있는 근거를 남긴다. 모델은 참고 의미 검토만 담당한다. 이는 현재 코드와 기록을 대조한 설계 판단이며, 수행하지 않은 대안 간 성능 비교 실험을 뜻하지 않습니다.

### 개발 중 문제·해결·남은 한계

기본 목록이 비어 있는데 기능 충족으로 오해할 수 있어 UI에 명시 계약 없음/미검증을 표시한다.

증거는 이 README의 관련 파일·검증 기록과 연결합니다. 운영 장애 기록이 없는 설계 위험은 실제 운영 장애로 주장하지 않습니다. 숫자는 각 차수의 실행 기록을 따르며, 이전 통과 수를 현재 코드의 새 실적으로 재사용하지 않습니다.
