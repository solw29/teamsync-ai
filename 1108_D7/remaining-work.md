## 준비 및 확인

- [x] main의 파이프라인, 로컬 Ruff·24개 회귀 테스트·6쌍 수기 계약 평가
- [x] `demo/s01-divide-zero` 검증 브랜치 준비·원격 푸시
- [x] S01에서 의도한 ZeroDivisionError 재현: 계약 테스트 1개 실패·1개 통과
- [ ] 클라우드 환경의 `api.github.com` 네트워크 허용 적용
- [ ] API 인증·저장소 권한 확인 후 검증 브랜치로 PR 생성

검증 브랜치의 실패는 시드 버그이며 main에 병합하지 않습니다. 클라우드의 Git 접근은 성공했지만 GitHub API는 프록시 CONNECT 403으로 차단되었습니다. `api.github.com` 추가를 환경 설정 초안에 저장했습니다. 토큰 추가가 필요하다는 증거는 아직 없습니다.

## 실행 순서

1. 새 연결로 API 조회를 재시도해 네트워크 및 API 권한을 확인합니다.
2. `demo/s01-divide-zero` → `main` PR을 생성합니다. Actions가 ruff 통과·pytest 실패를 실제로 기록하는지 확인합니다.
3. 검사 결과 선행 댓글 → AI 요약/유효 위치 리뷰 → 생성 테스트 상태 → 최종 댓글 갱신 및 Discord 전송을 확인합니다. 하나의 봇 댓글이 유지되는지 확인합니다.
4. 실패 잡이 있으면 로그에서 원인을 분류합니다. 키·Webhook 값과 응답 인증 정보는 기록하지 않습니다. 분석이 실패했을 때도 검사 결과가 남아야 합니다.
5. S01 버그 PR의 실행 로그와 댓글을 보존한 뒤 브랜치에 0 나눗셈 가드를 추가해 재실행합니다. 동일 초안이 버그에서 실패·수정에서 통과하는지는 별도 비교해야 합니다. 모델이 두 실행에서 다른 초안을 만들면 같은 테스트의 검출률로 계산하지 않습니다.
6. S02~S06 실제 PR 쌍을 순서대로 평가하고 D6 evaluation.csv에 실제 링크·수동 판정·시간을 기록합니다. 작은 표본의 결과만 보고합니다.
7. D9의 대본으로 실화면을 녹화하고 D10의 리허설 체크리스트를 채웁니다. 미실행 항목을 완료로 바꾸지 않습니다.

## 완료 증거

Actions run URL / PR URL / 댓글 URL / Discord 도착 확인 / 모델명 / 버그·수정 SHA / 동일 생성 테스트 / 이벤트~게시 시간 / 수동 오탐 판정이 필요합니다. 현재 실서비스 증거는 미수집입니다.
